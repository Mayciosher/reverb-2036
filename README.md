# 十年回响 · Reverb 2036

一个关于“十年后的音乐人如何过”的音乐游戏，课程选题 1（设计一款音乐游戏）× 选题 8（十年后的音乐人一天怎么过）。

一个让音乐人照见自己未来的游戏。

- 在线试玩：https://mayciosher.github.io/reverb-2036/ （仓库开启 GitHub Pages 后可用，手机和电脑都能玩）
- **离线版**：`dist/十年回响-离线版.html`，一个文件，字体和代码都打包在里面。发到微信群或 U 盘，双击就能玩，不需要网络，国内打开也不受影响。
- **安装到桌面**：用手机浏览器打开在线地址，选“添加到主屏幕”（iPhone 在 Safari 的分享菜单里），之后像 App 一样打开，断网也能玩。

仓库名 reverb 是“混响”，也就是录音棚里的回响；2036 是故事里的“十年后”。

## 玩法

十年后，也许没有人只是“音乐人”：一个人可能会写歌、会教课、会用 AI、会做生意。所以这个游戏不替玩家回答“你是谁”，只问一个问题：**十年后，音乐在你的生活里占几成？**

开局先选一个**心目中理想的音乐人**，再选**希望音乐在生活里占几成**，然后按顺序走完四关，没有回头路。走完以后生成一份**音乐人格画像**和**身份光谱**（音乐、教育、技术、商业、生活各占多少），和开局时的答案做对比，看看有没有忘记初心。

| 关卡 | 玩法 | 背景音乐 |
| --- | --- | --- |
| 1 饿死之前 | 2027 到 2036 年，每年 5 个选择、1 个音乐关卡。前几年是现实里正在发生的事，后几年是 AI 和行业变革之后才会遇到的事。选“他”或“她”会悄悄换掉一部分题目。数值到 0 或 100 会遇到“人生岔路”，共 19 种结局 | Lo-fi 爵士，每过一年多一种乐器（钢琴、贝斯、鼓、沙锤、弦乐、吉他、长笛、合成器、小号、人声合唱），数值越危险越紧张 |
| 2 音乐命运签 | 十年后走进“回声铺”，调音婆婆听你弹 8 个音，说出你第一关的过去；再抽三张牌、回答三个问题，得到下一个十年的签文和用你的旋律写成的命运旋律 | 大提琴持续音加竖琴 |
| 3 身兼数职的一天 | 2036 年的一天，换 7 个身份（广告配乐人、婚礼音乐顾问、AI 训练师……），7 个要求，每次从 AI 给的 3 个很接近的版本里挑对（调式、3/4 和 6/8、shuffle、音准、调外和弦、音色、终止式）。每个要求后有一个心理小插曲，最后选出“最像自己”的身份 | 合成器浪潮，越晚越快 |
| 4 十年回响 | 回看十年，回答四个终极问题（包括“你会怎么介绍自己”），写 4 个音交给管弦乐团，最后生成音乐人格画像 | 纯管弦乐，结局决定大调还是小调 |

第一关的每个结局都会告诉你“十年后别人怎么介绍你”和“音乐大约占你生活几成”。

第一关会悄悄变难：数字不再显示，只有快到危险时才提示；房租每三年涨一次，名气和热爱每年自然下降；每年有一张「真实故事改编」的卡（原型见 `docs/真实案例来源.md`），还有一定概率遇到意外；有些选择会在几年后回来找你。每局有 3 次「撤回上一步」。

第一关的十个音乐关卡有五种：上台演出（跟节拍按键）、凭耳朵调弦、听音模仿、心里的拍子（节拍器停了自己稳住）、人机辨听。

所有音乐都由浏览器 Web Audio 实时合成，没有使用任何现成歌曲。

最后的音乐人格画像可以一键生成**分享海报**（竖版图片），手机长按保存，电脑点按钮下载。

## 手机和耳机

- 开局会有一个约 10 秒的**耳机延迟校准**（跟着节拍点 8 下）。蓝牙耳机会慢 0.1 到 0.3 秒，校准后节奏关卡按你的延迟判定。主页可以重新校准，也可以跳过。
- 切到后台再回来，声音会自动恢复。iPhone 打开静音开关时网页可能没有声音，游戏会提醒「请关闭静音模式」。
- 设备卡顿时会自动减少同时发声的音符（进入省电模式），保证节奏不乱。

### 怎么加一张第一关的卡

先读 `docs/卡片写作规范.md`。每张卡都要有唯一的 `id`，不要改已有卡的 id。

在 `js/data.js` 的 `CARDS` 里复制一行，改这几处：

- `who`：谁说的；`say`：说了什么
- `w:[3, 6]`：最早第 3 年、最晚第 6 年出现。越往后的年份，越适合写未来的事
- `L` / `R`：左右两个选项。`t` 是按钮文字；`e:{m:钱, f:名气, l:热爱, o:原创}` 是数值变化
- `k`：这个选择背后的心理倾向，会进入最后的人格画像。可选：`ideal` 理想主义、`money` 务实、`auth` 忠于自我、`approval` 渴望被看见、`risk` 敢赌、`secure` 求稳、`ai` 拥抱技术、`bond` 重视连接、`avoid` 回避冲突、`fight` 正面硬刚、`burn` 透支自己

## 协作流程（GitHub Desktop）

1. 每次开始改之前，先点 **Fetch origin / Pull origin**，拿到别人的最新版本。
2. 用 VS Code 等编辑器改文件，直接双击 `index.html` 就能在浏览器里试玩。
3. 回到 GitHub Desktop，左下角写一句改了什么，比如“第一关新增 3 张卡”，点 **Commit to main**。
4. 点 **Push origin** 上传。
5. 改之前在群里说一声“我在改 ××”。两个人同时改同一个文件的同一段，就会出现冲突。

## 存档说明

进度和结局图鉴只存在玩家自己的浏览器里，换设备或清除浏览器数据就没有了。主页可以“清空进度，重新开始”，结局图鉴会保留。存档带版本号，游戏流程大改后旧存档会提示重新开始，不会卡死。
